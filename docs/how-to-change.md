# Как вносить изменения в DS 2.0

## 1. Что где менять

| Хочу | Где | Как |
|---|---|---|
| Устройство компонента: слои, отступы, варианты, свойства, иконка, текст | Components | Правлю компонент |
| Чтобы слой взял другой цвет / размер | Components | Выбираю у слоя другую **роль** (семантический токен) |
| Значение роли везде (например, hover у Primary) | Foundations | Меняю, на какой примитив ссылается роль — меняется во всех компонентах, темах и брендах |
| Нужного значения нет ни в одной роли | Foundations | Завожу новую роль (не примитив) |
| Иконка | Icons | Компонент `icon/<имя>`, один слой `glyph` |

Примитивы в компонентах не используем — они скрыты из библиотеки: примитив не переключается по темам и брендам.

## 2. Порядок после правки

1. Проверка (чек-лист `docs/dsp.md`): `Status:` в первой строке описания, всё на переменных, у новых переменных code syntax, ничего не переименовано и не удалено без `deprecated`.
2. **Publish**: `vX.Y.Z — что изменилось`.
3. Менялся Foundations → сразу после публикации, **с VPN**: плагин DSP Export → «Отправить в DSP».
4. В файлах, которые пользуются библиотекой (Components, продуктовые макеты) — **принять обновление**: Assets → библиотеки → Update. Иначе файл остаётся на старых значениях.
5. DSP открывает MR — проверяет и вливает разработчик.

## 3. Что ломает код (major)

Переименование или удаление переменной, свойства, значения варианта (Type, Tone, Size, State). Только так: `deprecated` → предупредить разработку → удалить в следующей версии.

## 4. Статусы

Эмодзи в названии страницы = `Status:` в описании = бейдж на борде.
- 🟠 draft — в работе, никуда не брать.
- 🟡 beta — в разработку и макеты, правки возможны. Борда → Dev Mode «Ready for dev».
- 🟢 stable — сделан в коде, сверен, есть на экране, ок Стефана. Борда → «Completed». API — только через deprecated + major.
- 🔴 deprecated — не использовать.
