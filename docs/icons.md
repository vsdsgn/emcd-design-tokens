# Иконки DS 2.0 — как устроены, как масштабируются, как экспортируются

## Источник правды — Figma, файл «◆ EMCD DS 2.0 — Icons», страница Icons

- Одна иконка = один компонент `icon/<смысл>` (латиница, дефисы, без размера в имени).
- Рисуем на сетке **24×24**, всё — **обводками** (stroke), не заливками. Заливка допустима только там, где форма по смыслу сплошная (точка, звезда-рейтинг, логотип сервиса).
- Внутри компонента — векторы с обводкой, никаких слитых контуров и скрытых копий.

## Толщина

- Толщина обводки привязана к токену `icon/stroke/regular` (коллекция Platform): Web — 1.5, App — 1.7. Её **не** правят руками.
- При изменении размера иконки толщина **не масштабируется** — остаётся токеновой. Так линия одинаковая на 16, 20, 24 и 32.
- Если для конкретного размера толщина выглядит не так — меняется токен, а не иконка.

## Масса (оптический размер)

Чтобы иконки выглядели одинаково «тяжёлыми», форма вписывается в keyline сетки 24:

| Тип формы | Пример | Габарит внутри 24 |
|---|---|---|
| Круг | history, user, settings | ≈ 19.5 × 19.5 |
| Квадрат | copy, calendar, wallet | ≈ 17 × 17 |
| Горизонтальная | card, cloud, mail | ≈ 20 × 15.5 |
| Вертикальная | lock, bell, document | ≈ 15.5 × 18.5 |
| Глиф (не масштабируем) | chevron, check, close, plus, minus, точки | свой размер, только центр |

Это ориентиры, финальная подгонка — на глаз. Форма всегда по центру сетки.

## Размер в интерфейсе

- Размер инстанса — только токенами `icon/size/*` (Platform): `sm` 16, `md` 20/24, `lg` 24/28, `xl` 32, плюс семантические `inline`, `control`, `nav`.
- Никаких `-x1`, `-x1,5`, `-x3` копий: одна иконка — все размеры.
- Для огромных экранов (4K/8K) иконки растут вместе с rem в коде — отдельные версии не нужны.

## Цвет

- Обводка привязана к `icon/primary`. В интерфейсе цвет меняется через токены `icon/*` (secondary, accent, danger…), не hex.

## Экспорт в репозиторий

Делает скрипт, руками ничего не экспортируем:

- `icons/svg/<name>.svg` — для web: обводки, `stroke="currentColor"`, `stroke-width` из токена (можно переопределить из CSS).
- `icons/flutter/<name>.svg` — для Flutter: те же формы, обводки **переведены в контуры** и слиты в один path (Flutter не масштабирует stroke так, как нужно).
- Имя файла = имя компонента без `icon/`.

## Сервисы и бренд

- Значки сервисов (Telegram, App Store, Google Play, YouTube…) — это иконки: `icon/social/<name>`, `icon/store/<name>`. Сплошные формы допустимы.
- Логотип EMCD (полный и сокращённый, по брендам) — **не иконка**, живёт в Components → Media (`logo`), с вариантами бренда.

## Источники форм

- **База — Remix Icon** (Apache 2.0): каркас для новых и перерисованных иконок. Берём композицию, пересобираем в наш стиль (обводка из токена, скругления, масса).
- **Iconly Pro** — добавка и fallback, добавляется вручную через плагин в песочницу. В библиотеку попадает только после пересборки по правилам этого документа. Платные ассеты в публичный репозиторий как есть не кладём.
- Рисуем с нуля, только если нужной метафоры нет ни там, ни там.

## Как добавить или поменять иконку

1. Нарисуй черновик в песочнице по правилам выше.
2. Пришли мейнтейнеру: что за иконка, где нужна, ссылка.
3. Мейнтейнер добавляет в библиотеку, публикует, запускает экспорт, пишет в CHANGELOG.
