# Производительность и загрузка

Обновлено: 2026-10-05. Тест: `npm run test:perf` (все движки) или `npm run test:perf -- chromium`. Страница-нагрузка `tests/perf/stress.html`: липкая стеклянная шапка, два пятна света, 40 карточек (треть — стекло, часть — свечение), таблица 80 строк с липкой стеклянной шапкой, шиммер скелетона.

## Подключение в вебе

```html
<head>
  <script src="/tokens/js/perf.js"></script>          <!-- блокирующий, до CSS: решает до первой отрисовки -->
  <link rel="stylesheet" href="/tokens/css/ds.min.css"> <!-- один файл вместо цепочки @import -->
</head>
```

- `build/css/ds.min.css` — все слои одним файлом (~60 КБ, **~8 КБ gzip**). `index.css` остаётся для разработки: это цепочка из 19 `@import`, браузер грузит их по очереди.
- `build/js/perf.js` (~4.5 КБ, без зависимостей) — перф-гард. Лучше вставить инлайном в `<head>`.
- Сервер: gzip или brotli для CSS/JS, долгий кеш с хешем в имени файла.

## Загрузка: один файл против цепочки (Chromium, gzip, эмуляция сети DevTools)

| Сеть | `index.css` (20 запросов) | `ds.min.css` (1 запрос) |
|---|---|---|
| Быстрая | CSS готов 175 мс | 55 мс |
| 4G (1.6 Мбит/с, RTT 150 мс) | 1.0 с | 0.4 с |
| 3G (0.4 Мбит/с, RTT 400 мс) | 2.6 с | 1.0 с |
| 2G (0.25 Мбит/с, RTT 800 мс) | 5.0 с | 2.0 с |

До загрузки CSS страница не рисуется, поэтому это же время — до первой отрисовки. На слабой сети один файл быстрее в 2.5 раза: решают задержки на каждый запрос, а не вес.

## Отрисовка: прокрутка, доля медленных кадров (> 25 мс)

Chromium в контейнере без GPU — блюр тут дороже, чем на реальном устройстве; важна разница режимов, а не абсолютные цифры. Замедление CPU 4× / 6× ≈ бюджетный Android / старый ноутбук.

| CPU | Base | Expressive | Expressive + `perf-low` |
|---|---|---|---|
| 1× | 1% медленных, 60 fps | 19%, 49 fps | 0%, 60 fps |
| 4× | 10%, 54 fps | **80%, 29 fps** | 15%, 52 fps |
| 6× | 16%, 50 fps | **86%, 25 fps** | 19%, 49 fps |

Вывод: на слабом железе Expressive роняет плавность вдвое, `perf-low` возвращает её к уровню Base. Значит, деградацию надо включать по факту, а не только по версии браузера.

## Перф-гард: когда включается деград-версия

`data-perf="low"` на `<html>` → токены дают Base (без стекла, блюра, света; контраст и вёрстка те же). Продукт может использовать тот же флаг, чтобы не грузить тяжёлое (Lottie, видео, крупные картинки).

| Сигнал | Когда | Где работает |
|---|---|---|
| Экономия трафика (`Save-Data`) | до отрисовки | Chromium |
| Медленная сеть: 2G / 3G (`effectiveType`) | до отрисовки; при смене сети пересчитывается | Chromium |
| `prefers-reduced-data` | до отрисовки | Chromium за флагом |
| Мало памяти: ≤ 2 ГБ, или ≤ 4 ГБ и ≤ 4 ядер | до отрисовки | Chromium |
| Медленные кадры: ≥ 30% кадров дольше 25 мс за первые ~1.5 с прокрутки (через 1 с после загрузки, только в Expressive) | на лету; запоминается на устройстве на 7 дней | **все браузеры**, включая Safari и Firefox |
| Старый движок (нет `backdrop-filter`) | CSS сам | все |
| Повышенный контраст / снижение прозрачности | CSS сам | contrast — все; прозрачность — Chromium |

Приоритет: решение продукта (`data-perf` уже стоит на `<html>`) → настройка пользователя → сохранённое «медленно» → сигналы. Настройка «Упрощённое оформление» в продукте: `emcdPerf.set('low' | 'high' | 'auto')`. Причина решения — в `data-perf-reason` на `<html>` и `emcdPerf.reason()` (для аналитики: стоит отправлять в Amplitude, чтобы видеть долю пользователей на деград-версии).

Пороги — `emcdPerf.thresholds`, подобраны по таблице выше: в Base на слабом CPU медленных кадров 10–19%, в Expressive — 80%+, порог 30% их уверенно разделяет.

## Что ещё не проверено

- Реальные устройства: бюджетный Android, iPhone на iOS 18 (минимум для Expressive), старый ноутбук на Windows. Эмуляция CPU не замедляет GPU, а блюр — это GPU.
- Шрифты: в токенах нет `@font-face`. Когда выберем новый шрифт — `woff2` с подмножеством кириллица+латиница, `font-display: swap`, `preload` основного начертания, запасной шрифт с `size-adjust`, чтобы текст не прыгал.
