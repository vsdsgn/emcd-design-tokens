# Как устроена система (коротко)

## Одна мысль

Компонент один на всех. Как он выглядит, решает набор независимых **осей** — коллекций переменных в Foundations. Продукт = выбор по одному режиму на каждой оси.

## Слои

```
Primitives            сырые значения: цвета (рампы 50–950, альфы), шкала размеров
   ↓ ссылаются
Brand                 чей продукт      EMCD · Geometria · WL Default
Theme                 светлая/тёмная   Light · Dark
Platform              где работает     Web · Mobile web · iOS · Android  (плотность + поведение)
Viewport              ширина           Compact · …
Style                 сколько декора   Base (по умолчанию) · Expressive
   ↓ используют
Components            кнопки, инпуты, карточки… — только семантические токены, никаких hex и чисел
   ↓
(всё уникальное продуктов — тоже в Components; отдельные продуктовые либы не заводим)
```

Оси не зависят друг от друга: меняешь одну — остальные не трогаются.

## Что за что отвечает

| Ось | Меняет | Не меняет |
|---|---|---|
| Brand | акцентный цвет, шрифт, радиусы, фокус | поведение, декор |
| Theme | светлое/тёмное | бренд, декор |
| Platform | размеры контролов, отступы, сила блюров, motion, поведение: отклик, «назад», оверскролл, хаптики, можно ли блюр | цвета |
| Viewport | раскладку и кегли по ширине | всё остальное |
| **Style** | декор: стекло, пятна света, тинты, кромки, прогрессивный блюр | структуру и поведение компонента |

## Base и Expressive

- **Base** — система по умолчанию. Чистая, без декора. Это то, что видят все продукты, и это же **откат** для любого случая, когда декор нельзя: слабое устройство, снижение прозрачности, нет `backdrop-filter`, Android (блюр).
- **Expressive** — тот же язык плюс декор. Включается явно и только когда: продукт — pool или Monitoring **и** устройство тянет рендер **и** браузер современный (Chromium 76+, Firefox 103+, Safari / iOS 18+), а снижение прозрачности не включено там, где браузер его сообщает.
- Декор живёт **внутри** тех же компонентов отдельными слоями; в Base они выключены токенами `decor/*` и нулевыми значениями. Поэтому Base не тяжелеет визуально и ничего не ломается при переключении.
- Что разрешено в Expressive и где — роли и бюджет экрана: `visual-language.md`, страница Foundations «🌗 Visual language».

## В Figma

Режим оси выбирается на фрейме или странице (панель Variables → режимы коллекций). По умолчанию: EMCD · Dark · Web · Base. Viewport — только ширина (узкое окно десктопа не становится мобильным вебом).

## В коде

Веб: атрибуты на `<html>` — `data-brand`, `data-theme`, `data-platform` (web · mobile-web), `data-style`, `data-perf`; CSS в проде — `build/css/ds.min.css` (один файл, ~8 КБ gzip), для разработки — `build/css/index.css`; в `<head>` до CSS — перф-гард `build/js/perf.js` (docs/performance.md). `perf-low.css` сам откатывает Expressive в Base при слабом рендере.
Flutter: `build/json/<brand>.<theme>.<ios|android>.json` (Base) и `….expressive.json`.

## Поток изменений

Figma Foundations → публикация (вручную) → экспорт переменных в `figma/export-*.json` → `npm run all` → `tokens/**` (DTCG) → `build/**` → git push → «обнови Claude DS» (артефакт для Claude Design, docs/claude-ds.md). Компоненты получают изменения после публикации Foundations и принятия обновлений в Components.

## Манифест компонентов (с 2026-11-12)

- `docs/ds-manifest.json` — машинное описание Figma Components: страница → наборы → статус, оси, варианты против полного произведения, свойства (тип, значение по умолчанию, в скольких вариантах привязано), вложенные компоненты, токены по слоям, значения без переменной, min / max, служебные слои, борда и её разделы.
- Снять: `scripts/figma/manifest.plugin.js` через `use_figma` (только чтение; `PAGES` — id страниц, ответ режется на куски по 18,5 KB, `CHUNK` — номер куска). Каждый ответ сохранить как `<батч>.<кусок>.txt` (батч `A*` атомы, `M*` молекулы, `O*` организмы).
- Собрать: `node scripts/manifest-build.mjs <папка> --date=ГГГГ-ММ-ДД` → `docs/ds-manifest.json` со сводкой.
- Манифест — вход для отчётов расхождений (`docs/audit-*.md`) и для паритета с кодом: `npm run parity` (`scripts/parity.mjs`, в CI). Проверяет: токены компонентов есть в `tokens/**`; статусы `claude-ds/status.json` = Figma; манифест кода (`docs/code-manifest.json` или `--code=`, формат — в шапке скрипта) = оси, свойства, значения по умолчанию, токены. Известные расхождения со сроком — `docs/parity-baseline.json`. Контракт компонента `docs/components/<name>.md` должен совпадать с манифестом.

## Базовые служебные компоненты и контракты (с 2026-11-12)

- Служебная база — набор с именем на «_» на своей странице (первая: `_Field base`). Компонент семьи = надстройка с вложенным раскрытым экземпляром базы; оси надстройки повторяют оси базы; своих слоёв рамки, кольца фокуса и зон у надстройки нет. Семьи перечислены в `FAMILIES` скрипта `audit-parity.plugin.js` (проверка BASE). Вторая база — `_Selection control`: строка выбора со слотом `Control`, в слот ставится глиф (`_Checkbox control`, `_Radio control`, `_Toggle control`); Hover, Pressed, Status, Tone и кольцо живут в глифе, поэтому у базы только Default и Disabled. BASE: если у базы нет значения оси надстройки, база обязана быть Default; оси глифа в слоте обязаны совпадать с надстройкой («BASE глиф»).
- Третья база — `_List row`: строка списка (Type Menu | Option | List) со слотами Leading / Trailing, глифом выбора и галочкой; надстройки — Menu item, Multiselect option, List item. Ловушка Figma: у свойства замены экземпляра (instance swap) одно значение по умолчанию на весь набор — `swapComponent` в одном варианте меняет глиф во всех. Разное состояние вложенного глифа по вариантам задаёт надстройка вариантным свойством глифа, не база.
- Четвёртая база — `_Overlay surface`: плавающая поверхность (Kind Tooltip | Popover | Toast | Modal | Sheet — фон, радиус, тень, блюр материала). В надстройке это первый слой `overlay surface` — экземпляр во весь корень (absolute, растянут); у корня надстройки нет своей заливки и тени, clip выключен, остаются обводка, радиус (та же переменная), отступы и ширина. Обводка не в базе: INSIDE на вложенном слое уменьшала бы вариант. Стиль эффектов нельзя совместить с блюром, поэтому у Popover и Sheet эффекты без стиля, числа равны Elevation (`OVERLAY_FX`). Проверка OVERLAY в `audit-parity.plugin.js`, таблица «набор → Kind» — `OVERLAY`. Контракт: `docs/components/overlay-surface.md`.
- Служебные слои (страница `_Service layers`): `_Focus ring`, `_State layer`, `_Hit area`, `_Safe margin`. Компонент ставит экземпляр с прежним именем слоя (`focus ring`, `state layer`, `hit area · overlay`, `safe area · outer`) и меняет только размер, радиус и видимость. Аудиты проверяют сам экземпляр, внутрь не заходят. Подробно: `docs/components/service-layers.md`.
- Контракт компонента: `docs/components/<name>.md` по схеме `docs/component-contract.md`. Контракт = описание в Figma = борда v3 = манифест.
- Аудиты по одной странице (в том числе служебной): `PAGES` в `audit.plugin.js`, `variables-check.plugin.js` (id страниц) и `audit-parity.plugin.js` (имя или id).
- Контракты beta-наборов собирает `npm run contracts` (`scripts/contract-build.mjs`): машинная часть — из `docs/ds-manifest.json`, рукописная — из `scripts/contract-data.mjs` (одна запись на набор). Файл в `docs/components/` руками не править; `npm run contracts -- --check` в CI падает, если файл разошёлся с манифестом. Контракты баз и пилотов (field-base, input, textarea, selection-control, list-row, overlay-surface, service-layers) — ручные, генератор их не трогает. Для атомов и молекул не в beta тот же скрипт пишет контракт-заготовку (заголовок «контракт · draft»): манифест + `scripts/contract-draft-data.txt` (строка на набор: что это | когда | когда нет | a11y | legacy — выжимка описания Figma) + замечания из `scripts/draft-findings.mjs` (те же правила, что у `npm run draft-audit`). При переводе набора в beta — завести запись в `contract-data.mjs`, заготовка заменится полным контрактом.
- `audit-parity` (DESC) ловит экранированные сущности в описании набора (`&amp;`, `&quot;`).
- Агентный слой: `npm run agent-docs` (`scripts/agent-docs.mjs`) собирает `llms.txt` (карта репо для ИИ-агента), `design.md` (принципы, роли цвета, модель состояний, выбор компонента) и `docs/api.md` (ожидаемые props beta-наборов) из манифеста и `contract-data.mjs`; `--check` в CI. Руками эти три файла не править.
- Аудит draft-наборов: `npm run draft-audit` (`scripts/draft-audit.mjs`) собирает `docs/audit-draft.md` из манифеста — что мешает перевести набор в beta (DESC, MATRIX, AXES, PROPS, MINMAX, RAW, SERVICE, BOARD); `--check` в CI. В Figma не ходит, наборы не меняет.
- `state/hover`, `state/pressed` — проценты прозрачности слоя: в CSS сборка отдаёт число 0–1 (`--state-hover: 0.06`), во Flutter-JSON — проценты (`stateHover: 6`). Правило — `isOpacity` в `scripts/build.mjs`.

## Замена набора на месте (с 2026-11-13)

Рецепт отработан на Input и Textarea; один вызов `use_figma` на набор, перед пакетом — точка в Version history (делает Стефан, API не умеет).

1. У всех экземпляров набора (`variant.getInstancesAsync()`, только с предком-страницей) снять значения BOOLEAN / TEXT по имени свойства до `#`.
2. В каждый вариант: клон первого ребёнка варианта-пилота → `appendChild` → `layoutSizingHorizontal = 'FILL'`, `isExposedInstance = true`; старых детей удалить; отступы, интервал и привязку `minWidth` скопировать с пилота.
3. `set.deleteComponentProperty(key)` для всех не-VARIANT свойств набора.
4. На `instance.children[0]` (слой базы) — `setProperties` для значений, отличных от умолчаний базы; шрифты загрузить заранее.
5. Проверки: `audit`, `variables-check`, `audit-parity` по страницам набора и базы; размеры экземпляров до / после; обрезания родителями; снимки набора и борды v3.
6. Переснять батч манифеста, `npm run contracts`, `agent-docs`, `draft-audit`, `parity`, `exceptions`.

Приёмы: слот вложенного экземпляра — `slot.children[0].swapComponent(…)` (`appendChild` ломается); удалённый компонент — `figma.importComponentByKeyAsync(key)`; рамка HUG со скрытыми детьми держит прежний размер; для нескольких страниц в одном вызове — `await page.loadAsync()` вместо переключения страницы; `figma.skipInvisibleInstanceChildren = false` в начале.
Привязка текста к строковой переменной (сетки языков) при замене теряется: до замены запомнить `boundVariables.characters`, после — вернуть `setBoundVariable('characters', v)`.
Экземпляр надстройки не HUG (растянут или фиксирован): слою базы внутри поставить `layoutSizingHorizontal = 'FILL'`.
Панели (база — слой, а не весь вариант): клон слоя `overlay surface` пилота → `insertChild(0)` → `layoutPositioning = 'ABSOLUTE'`, `resize` по корню, constraints STRETCH; у корня снять заливку, тень, стиль эффектов и clip; привязки корня и вложенных слоёв выровнять по пилоту обходом пары деревьев. Свойства и экземпляры не трогаются; до и после сравнить размеры всех экземпляров. В манифесте такой набор узнаётся по `_Overlay surface` ×вариантов во вложенных (`DRAFT_BASE` без `props`).
Описания наборов: без кавычек (`role=dialog`) — Figma экранирует `"` в `&quot;`, при копировании описания сущности нарастают.
Прогон плагина по нескольким страницам одним вызовом MCP: задать `PAGES`, `setCurrentPageAsync` заменить на `page.loadAsync()`.
Частичная пересъёмка манифеста: если ответ плагина велик, снять только изменчивые поля и хеш остальных, сверить хеш с сырьём и влить скриптом — руками сырьё не править.
Вариант, который выбывает (`State = Selected` → булево Selected): до снимка `swapComponent` его экземпляров на Default и пометка «Selected = true»; вариант удалить, когда экземпляров не осталось; после удаления переложить набор (варианты и размер рамки) — Figma оставляет дыру.
Слоты (SLOT): до замены снять подпись содержимого слота (главный компонент экземпляра, текст) у экземпляров, где оно отличается от варианта; после — вернуть `swapComponent` / `characters` в слоте базы.
Переименование свойства при замене — карта «старое → новое» в снимке значений (`Title` → `Label`).
Draft-набор на базе: `DRAFT_BASE` в `contract-build.mjs` (шапка, раздел 5 и 14 заготовки), `BASES` в `draft-findings.mjs` (SERVICE не проверяется — слои в базе), `BASE_PROPS` в `agent-docs.mjs`, `SERVICE_DONE` в `audit-parity.plugin.js`.
Частичная пересъёмка манифеста: снять только изменённые наборы, влить в сырьё батча по id набора, пересобрать.
Базы и служебные слои: `scripts/figma/manifest-bases.plugin.js` → `bases.json` в папке сырья → раздел `bases` манифеста. Нужен `parity`: токены надстройки после замены живут в базе и глифах. Новая база — добавить страницу в `PAGES` плагина и переснять.

## Правки набора без замены (пакет beta 2026-11-13)

- **Вариант по умолчанию** — первый ребёнок набора. Сменить: переставить нужный вариант на первое место (`set.insertChild(0, variant)`); порядок значений оси и экземпляры не меняются.
- **Порядок осей** — из имён вариантов. Сменить: переименовать все варианты в новом порядке (`Size=…, Selected=…, Tone=…, State=…`); экземпляры не ломаются.
- **Описания** — без прямых кавычек и угловых скобок: Figma их экранирует, `audit-parity` ловит как DESC.
- **Строка «Поиск:»** в описании содержит алиасы в неверной раскладке (`,tql;` = «бейдж») — намеренно, не удалять.
- **Булево свойство vs ось-тумблер**: булево свойство Figma только показывает / скрывает слой. Если значение заменяет один слой другим (спиннер вместо иконки у Icon button), делается ось `False | True` — в панели это тот же тумблер, в коде — boolean. В `audit-parity` такая ось разрешается поимённо (`Loading` у Icon button), с записью в шапке скрипта. Left / Right в осях запрещены без исключений.
- **`audit-parity`**: обходит и отдельные COMPONENT вне наборов (DESC, MINMAX); записанные исключения min / max — в `MINMAX_OK` скрипта (с 13.11 пуст), строка в `docs/exceptions.md` обязательна; ширина слоя ABSOLUTE + STRETCH числом не считается; `Selected` и `Status` — законные оси Off / On.
- **Новые `size/*` после Publish Foundations**: экспорт → `npm run all` → очистить `pendingPublish` в `docs/parity-baseline.json` → `scripts/figma/bind-sizes-extra.plugin.js` в Components (карта «набор → слой, свойство, токен, значение»; привязывает только число, равное токену; повторный запуск безопасен). `maxWidth` текстового слоя Plugin API не привязывает. Экземпляры с переопределённым min / max привязку главного не наследуют — их добавляют в карту отдельной строкой.
- **Дельта манифеста**: пересняты только затронутые наборы, влиты в сырьё по id, затем `node scripts/manifest-build.mjs <сырьё> --date=…`. Перед вливанием — копия папки сырья.
- **Сырые числа → переменные**: `scripts/figma/bind-raw.plugin.js` (зазор и отступ N → `space/N`, обводка 1 / 1.5 / 2 → `border/width/default` / `icon/stroke/regular` / `border/width/strong`, точечные правила — карта `R`). Повторный запуск безопасен. Не трогает экземпляры, отрицательные зазоры, заглушку `content` у Card, min / max текстовых слоёв — это реестр исключений.
- **Страницы компонентов** все скрипты берут по имени: эмодзи статуса (🟠🟡🟢🔴) или `_` у служебных баз. По индексу — нельзя: порядок страниц меняется.
- **Ответы `use_figma` → файлы сырья**: ответы лежат в журнале сессии (`~/.claude/projects/…/<сессия>.jsonl`); вызовы подписывать `MANIFEST read-only batch <X> chunk <N>` и раскладывать в `<X>.<N>.txt`. Если кусков у батча стало меньше — старый лишний файл удалить, иначе `manifest-build` падает на разборе JSON.
- **Контракты beta**: умолчания, приёмка и остаток — в `scripts/contract-data.mjs` (`defaults`, `accept`, `todo`); после правки набора обновить их и `npm run contracts`.
- **Фиксированные width / height → переменные**: `scripts/figma/bind-dims.plugin.js` (карта «набор → слой, свойство, токен, значение»; привязывает только FIXED-размер числом, равный токену; токены, которых нет в библиотеке, возвращает в `missing` — после Publish запустить ещё раз).
- **Аудит draft** (`npm run draft-audit`, правила — `scripts/draft-findings.mjs`): списки допусков `RAW_OK`, `MINMAX_OK`, `BOOL_OK`, `NO_FOCUS` зеркалят `docs/exceptions.md` и списки `audit-parity` (`SIZE_OK`, `SIZE_PENDING`, `BOOL_OK`). Строка реестра снята — убрать из обоих.
- **Блок «— · Не собрано в этой версии»** на борде v3: разделы, которых у компонента нет по смыслу, перечислены с причиной; `draft-audit` тогда не требует эти разделы.
- **Описания Figma** — также без амперсанда; при записи он экранируется.
- **Оверрайд цвета во вложенном экземпляре** проверять отдельным вызовом чтения: в том же вызове значение читается как записанное, но может не сохраниться.

## Борды из контрактов и скрипты в текстовом узле (с 2026-11-14)

- **Генератор борд v3:** `scripts/board-data.mjs --out=<папка>` собирает по борде JSON из контракта и манифеста (`usedIn` — где набор вложен, для раздела 07). `scripts/figma/board-v3.plugin.js` строит борду: шапка, 01–12, «Не собрано», 07 «Примеры в составе» (вариант по умолчанию родителя, свойство, показывающее компонент, включено). Старая борда уходит на страницу архива (`D.archive`), до «ок» Стефана не удаляется; повторный прогон уже собранной — `D.board` = её id, без `D.archive`.
- **Скрипт в текстовом узле.** Большой скрипт (генератор, съёмка манифеста) кладётся текстом в узел на временной странице «⚑ Генератор · временный»; вызов — `new AsyncFunction('D', node.characters)(D)`. В `use_figma` идут только данные. Файл в репо и узел держать одинаковыми: после правки сверить длину и контрольную сумму `Σ code(i)·(i mod 97 + 1) mod 1e9+7`. Защита данных: в начале вызова та же сумма по `JSON.stringify(D)` (длина в UTF-16: эмодзи — два символа).
- **Манифест по пачкам:** `manifest.plugin.js` в узле принимает `ARGS = { pages, chunk }`; ответы подписывать `MANIFEST read-only batch <X> chunk <N>`, раскладывать из журнала сессии; дельта — пачка изменённых страниц, вливается в сырьё заменой страниц по id.
- **Вариант по умолчанию и порядок значений оси** Figma берёт по положению на холсте (левый верхний вариант), а не по порядку слоёв: после добавления вариантов раскладывать набор сеткой (State по столбцам, Default первым) и проверять `defaultVariant`. Порядок значений в выпадающем списке API не меняет.
- **Иконки в манифесте:** иконка — главный компонент `icon/…` (регулярка `^(icon|ic)/`). Прежняя `^(icon|ic)[ /_]` считала Icon button иконкой — вложенность Icon button терялась (исправлено 14.11).
- **Скрытый экземпляр внутри компонента** (спиннер Button при Loading = false) не отдаёт детей через API: чтобы перекрасить, временно включить свойство по умолчанию (`editComponentProperty(key, { defaultValue: true })`), править, вернуть.
- **Цвет из библиотеки Foundations** привязывается через `figma.variables.importVariableByKeyAsync(key)`; ключи — `figma.teamLibrary.getVariablesInLibraryCollectionAsync`.
