## 0. Решения 16.11 (обязательны для новых экранов)

1. **Навигация Compact** — `Tab bar` везде: App, WL и мобильный веб пула (бургер убираем). Подразделы — `Tabs` под шапкой.
2. **Sidebar Web** — один вид: плавающая панель L1 с отступом `space/12` (как Web App и Monitoring); Geometria и B2B admin переходят на него. Глобальный Top bar на Web не делаем.
3. **Детали объекта** — Web: отдельная страница (Side panel — когда выйдет из парковки); Compact — `Sheet`. Широкий `Modal` для деталей не используем.
4. **Период графика** — ряд `Chip` в шапке `Chart card` (Web S справа, Compact M равными долями; 22.11 приведено к правилу 19.11 — не `Segmented`).
5. **Фильтр списка по статусу** — ряд `Chip` S с Meta-счётчиком; `Tabs` — только разделы.
6. **Ряд метрик** — отдельные `Stat card` в сетке (`layout/gutter`), не одна карточка с разделителями.
7. **Сводка воркеров** — строки со `Status` и числом (как Web App); цветные плитки и полосу долей не используем.
8. **Детали строки истории** — `Sheet` (контракт Transaction); раскрытие на месте не делаем.
9. **Успех операции** — деньги (вывод, обмен, пополнение): Status screen; настройки и мелкие действия: `Toast`.
10. **«Сохранить» в формах настроек** — внизу формы; мгновенные настройки — `Toggle` без кнопки.
11. **Промо** — одна `Promo card` на экран; реферальное без картинки — `Suggest`.
12. **Подпись поля** — Above в формах; On border — только калькуляторы и панели фильтров.
13. **Строки таблицы** — `Table row` с разделителем внутри карточки L1; строки-карточки не используем.
14. **Числа** — к токенам: поле страницы `layout/margin`, зазор между карточками `layout/gutter`, между секциями `space/section`, от шапки до контента `space/24`. Внутренний отступ карточки — `Card` Size (M 16 на Compact, L 28 на Web); нового токена не заводим.
15. **Кандидаты в Base** (Top bar, Stepper, Table-контейнер, тулбар фильтров, Search, карусель, Section header, Setting row) — в парковке; пока собираются из существующих наборов по разделу 3.

## 0.0 Правила 17.11 (ревью Стефана, `docs/screens-review-2026-11-17.md`)

**Размеры контролов.** Web: M 40 — по умолчанию (поля, Select, Segmented, кнопки); S 32 — таблицы, панели фильтров, шапки карточек; XS 24 — служебные мелочи (язык, свернуть сайдбар, действия строки таблицы); L 48 — только главная форма шага (вывод, вход). XL снят на уровне системы (2026-11-17, «ок» Стефана): у Icon button, Segment / Segmented, Input / Select / Textarea и `_Field base` вариантов XL больше нет. App: L 48 — по умолчанию, M 40 — вторичное, Button XL 56 — только одна главная кнопка экрана App. Табы-заголовок страницы — Tab / Tabs Size=Page (до 17.11 — XL, текст 20): это навигация, не контрол. Amount XL и Coin XL — размеры текста и медиа, не контролов, остаются.

**Моноширинный шрифт** — только подписи осей и шкал графиков (Chart plot). Таблицы, суммы (Amount), тултипы, аннотации, метрики — шрифт текста с табличными цифрами. Применено 17.11: Amount, Key-value row, Progress, Progress circle → `font/family/text`. Исключение — Address (адрес кошелька, хеш): моно для различимости символов (0/O, 1/l).
**Уровни текста в тёмной теме (19.11, Стефан: «переборщили с контрастом»).** `text/secondary` и `icon/secondary` — белый 56 % (было 72), `text/tertiary` и `icon/tertiary` — 48 % (было 56), `text/disabled` — 40 %. Контраст: secondary ≥ 6:1, tertiary ≥ 4.7:1 на L0–L3 (AA). Светлая тема без изменений. Вторичное (единицы, подписи метрик, неактивные пункты сайдбара и табов) — `text/secondary`; служебное (оси, подписи под числом) — `text/tertiary`.

**Выгрузка отчёта (19.11).** Кнопка «Выгрузить» / «Выгрузить отчёт» — иконка `icon/file-excel` (выгружается таблица), не `icon/download`. `icon/download` — скачивание файла (документ, приложение).

**Автовыгрузка (22.11, по production Web App «Выгрузка»).** Кнопка «Выгрузить» при включённой автовыгрузке — свойство `Badge` у Button: Badge S «Авто» + `icon/history` после подписи (не плашка поверх угла кнопки, не `icon/refresh`). Настройка — в той же форме выгрузки (Web — Modal 600 «Выгрузить историю», App — Sheet): блок Card Level 2 «Автовыгрузка» — Section header M + Toggle в Trailing, подпись «В 12:00 формируем отчёт…»; при Toggle On — Radio card ×3 (раз в неделю / месяц / три месяца; у выбранной — детали) и Button Secondary «Сохранить расписание» (Web); в App — одна кнопка «Сформировать и сохранить расписание». Production делает две панели рядом (форма | расписание) — в DS одна колонка: модалка не шире 600, на App та же последовательность. Макеты: Web Migration «История · выгрузка (модалка) · Web · DS 2.0», App Migration «Выгрузка · автовыгрузка · App · DS 2.0».

**Цвета графиков (17.11).** Основная серия (хешрейт) — бренд `border/accent`; остальные серии — `data/2…8` по порядку (реджекты — `data/4`). Маркер легенды — того же цвета, что серия. Подписи осей — `font/family/mono`, `type/label/sm`, `text/tertiary`; по X не больше 6 меток (на мобильном — 3).

**Числа** (решение 17.11, главнее `typography-l10n.md` для интерфейса майнинга): десятичная точка во всех локалях (`535.15`), разряды — пробел (`123 456.78`), валюта перед числом (`$3.17`, `≈ $78.90`), тикер после (`0.00143210 LTC`).

**Иерархия навигации** (уровень → компонент; 19.11 — сверено с Monitoring, самая глубокая навигация: сайдбар → список устройств → карточка устройства → разделы → вид метрик → период):
1. Продукт / раздел приложения — Sidebar · Nav item (Web), Tab bar (App).
2. Раздел продукта (Дашборд · Воркеры · История; Monitoring: Площадки · Устройства) — Tabs Page в шапке страницы (Web), Tabs M с прокруткой до края (мобильный веб).
3. Подраздел списка (Все воркеры · Активные 2…; Monitoring: Активные 55 · Ожидание 12) — Tabs M (Web) / S (Compact) со счётчиком; статус — Status dot.
4. Объект (устройство, площадка, воркер) — Modal (Web) или Sheet / экран с Back + заголовок (Compact). Breadcrumbs не используем: в Monitoring их нет.
5. Разделы объекта (Метрики · Пулы · События) — Tabs M (Web) / S (Compact): на шаг меньше уровня, в котором объект открыт.
6. Вид одного набора данных (Список / Группы; Начисления / Выплаты; Все метрики · Хешрейт · Платы) — Segmented, 2–4 значения; на Compact больше 3–4 — ряд Chip с прокруткой.
7. Фильтр и период (24 ч · 7 д · 30 д, статус, «Без владельца») — Chip, выбранный — белый инверсный; фильтр по объекту (площадка, монета) — Select; на Compact, если места нет, период — Select compact.
Правила: каждый уровень вниз — на шаг меньше (Page → M → S); уровень не пропускается вверх (Chip не переключает разделы, Segmented не заменяет Tabs); **период — всегда Chip, не Segmented** (в Monitoring, Web App и App период — отдельные кнопки с белым выбранным; Segmented в Monitoring только для вида метрик).
Ширина табов (20.11, Стефан): на Compact (мобильный веб, App) вкладки растягиваются поровну на ширину, если все помещаются без прокрутки (`fill`); не помещаются — по содержимому с прокруткой. На Web desktop — всегда по содержимому.

**Вертикальная сетка отступов — лестница по смыслу** (Web, Expanded; 18.11, Стефан: «не везде 32»):
- 40 — от краёв вьюпорта и сайдбара до контента; от шапки (табы-разделы) до первого элемента страницы;
- 32 — от «меню» экрана (то, что меняет контент: монета, вид Список / Группы, фильтры) до контента;
- 24 — между блоками контента (сводка → таблица, график → плитки), между строками меню; внутри карточки между группами (табы → поиск → таблица); отступ карточки L — 24 сверху и снизу, 32 по бокам; карточки со списками и таблицами — Padding M;
- 16 — между элементами составного блока;
- В макете: `content` (40) → `header` + `body` (32) → `menu` + `blocks` (24).
- Мобильный веб и App: 16 — поля экрана; 12 — между блоками; 24 — от меню экрана до контента; внутри карточки 16 / 12.
- 8 — между связанными элементами (подпись → значение, иконка → текст в группе);
- 4 — плотные пары (значение → фиат, сумма → тикер).
App: 8 / 4 — как на Web.

**Стек монет и аватаров:** обводка элемента = цвет подложки, на которой лежит стек (по уровню L0–L3). Карточка внутри листа — на уровень светлее листа.

**Мобильный веб ≠ App:** ориентир — текущий мобильный веб (шапка с балансом, аккаунтом и бургер-меню). Tab bar — только App; для мобильного веба с >5 разделами — меню (Sheet), не Tab bar.

## 0.1 Пилот 16.11 — «Воркеры · Web · Dark» (Components, страница «🧪 Пилот · экраны»)

Собран из ранней сборки по решениям раздела 0: фильтр статусов — ряд `Chip` S с Meta; поле страницы и зазор сайдбар → контент — `layout/margin` (Viewport=Large, 40); карточка — отступы `space/24` и `radius/container` как у `Card` Padding=L, зазор `card/gap`; кнопка страницы — `Button` M.
Что показал:
- **Таблица собирается вручную**: строки — фреймы из `Table cell` фиксированной ширины, не тянутся по ширине карточки (последняя колонка упирается в край). Подтверждает кандидата «Table-контейнер» (колонки: доли / fill, липкая шапка).
- **Шапка раздела** — `Tabs` XL + текстовая кнопка, не `Page header`: в Web App заголовка нет, разделы = табы. Правило: `Page header` Large с Show tabs и пустым Title не делаем — для разделов-табов допустим ряд `Tabs` XL + действие (записать в `Page header`, решение — после пилота Compact).
- **Отступ шапка → контент** 24 (`space/24`) читается лучше, чем `space/section` 64; `space/section` — только между самостоятельными секциями. Раздел 0 п. 14 уточнён.
- `card/padding` в Foundations = 16 на всех Viewport — для Web-карточек используем Padding вариантов `Card` (L = `space/24`); токен `card/padding` пересмотреть.

Compact (App, 375, Viewport=Compact) — «Воркеры · Compact (App) · Dark · пилот 16.11»: `Page header` Compact (без действий) → `Select compact` (монета) → ряд `Chip` S с прокруткой вбок → `Input` поиска → список `List item` M → `Tab bar` (Воркеры выбран). Поля `layout/margin` (16), зазоры `space/16`.
Что показал:
- **Нет Top bar** — сверху пустое место под статус-бар (56); кандидат в парковке подтверждён.
- **Show leading у List item** — через вложенную базу `_List row` (exposed в панели свойств): для воркеров Leading выключен. Правило блока: у воркеров Leading нет, у монет и операций — есть.
- **Статус воркера** — `Status` S в слоте Trailing (`_List row`), не текст; в пилоте так и собрано.
- Таблица на Compact не нужна: строки `List item` (название + хешрейт / реджекты, справа статус и время) — правило блока подтверждено.

Пилот «Вывод · Compact (App) · Dark»: `Page header` Compact → форма (`Select` L «Сеть», `Input amount` с балансом и «Макс», `Input` L Above «Адрес кошелька») → сводка `Key-value row` (комиссия, итог Total) → распорка → `Button` Primary XL на всю ширину над safe area.
Что показал и что исправлено:
- **Select не растягивался** (поле 320 числом) — исправлено в наборе: `field` Fill, кольцо фокуса тянется.
- **Key-value row Total — другой шрифт значения** (Roobert вместо моноширинного): числа в столбце не выравнивались — исправлено, Total тоже `font/family/mono`.
- Порядок блока 3.7 подтверждён: что → куда → сколько → комиссия и итог → кнопка.
- На вложенном экране нужен Top bar «назад» (парковка) — сейчас вместо него `Page header` Compact.

Пилот «История · Compact (App) · Dark»: `Page header` Compact → ряд `Chip` S по типу операции (прокрутка) → группы по дате (подпись даты — текст `text/secondary`) → строки `Transaction` → `Tab bar` (История выбрана).
Что показал:
- **Внутри группы по дате в строке только время** («14:02»), дата — в подписи группы; иначе дата дублируется.
- Подпись группы — простой текст, не компонент: довод за кандидата «Section header» (парковка).
- Отклонённый вывод — без знака суммы (баланс не изменился); начисление — `+` зелёным, вывод — `−` нейтральным: правило Amount подтверждено.

## 0.2 Конструкции (организмы в Components, с 19.11)

Повторяющиеся блоки экранов — наборы в Components (страницы 🟠 в разделе «Организмы»), а не ручные сборки. Экран собирается из них; правка — в наборе, экраны подтягивают через Publish.

| Конструкция | Где | Состав | Правило |
|---|---|---|---|
| `Top bar` · Mobile web | корневые экраны мобильного веба | слот Logo · аккаунт · баланс · «Меню» | над Tabs M разделов; App — следующим вариантом |
| `Status summary` | дашборд майнинга | 3 × Stat card Align=Center + Link; Layout Column (Web) / Row (Compact) | порядок Danger → Warning → Neutral |
| `Promo carousel` | низ мобильного дашборда | слот Slides (Promo card M 311) + Page indicator | одна на экран, ниже рабочих блоков |
| `Action bar` | низ мобильных «Воркеры», «История» | 1–2 Button M поровну, `surface/level-0` | не на экранах с Tab bar и не на Web |
| `Page header` (есть) | шапка страницы Web / Compact | заголовок, действия, Tabs | — |
| `Sidebar` (есть) | Web | Header · Nav · Promo · Footer | — |
| `Chart card` (есть) | график с периодом | Chart metric · Chip-период · Chart plot · Legend | период — Chip |

Ещё не вынесены (кандидаты, по мере повторения на втором продукте): сводка с полосой фактов (Card + Amount L + факты), панель фильтров над таблицей (Select + Date range + Button), блок фактов монеты на Compact (List item M).

## 0.3 Чеклист вёрстки экрана (20.11, после «почти все экраны с косяками»)

Перед сдачей экрана — `scripts/figma/layout-audit.plugin.js` (use_figma, `ARGS = { page, filter }`) → 0 замечаний, потом глазами в полном размере.
1. **Высоты — по содержимому.** Свои фреймы и экземпляры в слотах — Hug; Fixed только у кадра экрана и листа. Найдено: колонки строк Watcher-link высотой 10, поля калькулятора 18.
2. **Поле родителя.** Ничего не вылезает за поле карточки (список «Уведомлений» шёл до края карточки). Горизонтальная прокрутка — только у рядов Chip, карусели и табов.
3. **Таблица.** Ширины колонок шапки = ширины ячеек строк; выравнивание содержимого ячейки = выравниванию шапки (Start / End). Колонка суммы — не уже содержимого (Coin + Amount + тикер), иначе узкой делается соседняя колонка или сводка (Сводка Истории — 320).
4. **Отступы и зазоры — токены** (`space/40` есть); никаких «18» для подгонки: выравнивание по центру ряда.
5. **Монета = подпись.** Символ в Select / Select compact совпадает с тикером (KAS ≠ Tether по умолчанию).
6. **Слоты экземпляров не обновляются Publish'ем.** После правки содержимого слота в наборе (шеврон Select, логотип Top bar) — пройти экраны и поправить экземпляры.
7. **Картинка промо — своя или никакой.** Плейсхолдер `image` (серый квадрат) на экране недопустим; картинку с чужой цифрой («14%» к «до 8%») не ставить.
8. **Подпись не сжимается в Segmented** — сегменты по содержимому (Hug), не Fixed 96.
9. **Подпись Checkbox / Radio / Toggle — Hug** (по содержимому, бейдж сразу за ней). Fill + перенос — только если подпись длиннее строки. Фиксированную ширину не ставить: после Publish она сжимает подпись до слова (21.11).

Одна шкала для всех продуктов (майнинг, Мониторинг, WL B2B / B2C). Значение берётся из токена — режим Viewport кадра даёт Web или мобильное значение; чисел и `space/*` на месте этих ролей нет.

**Зазоры**

| # | Роль | Web | Моб. | Токен |
|---|---|---|---|---|
| 1 | Внутри контрола | — | — | токены компонента |
| 2 | Связка: подпись → значение, число → единица | 4 | 4 | `space/4` |
| 3 | Элементы в ряду: кнопки, чипы, фильтры | 8 | 8 | `space/8` |

| 5 | Строки формы, факты «подпись / значение» | 16 | 16 | `space/16`; List item / Table row — без зазора |
| 6 | Блоки внутри карточки: шапка → содержимое, группы | 16 | 12 | `surface/gap` |
| 7 | Между карточками страницы (ряд и колонка) | 16 | 12 | `layout/gutter` |

| 9 | Между разделами (Section header L + контент) | 40 | 24 | `space/section` |
| 10 | Поле страницы | 40 | 16 | `layout/margin` |

**Отступ внутри поверхности — три ступени, всегда симметрично**

| Ступень | Web | Моб. | Токен | Где |
|---|---|---|---|---|
| L | 24 | 16 | `surface/padding/lg` | карточки страницы (Card L), Chart card, Modal, Side panel, Sheet, Promo card M / L |
| M | 16 | 12 | `surface/padding/md` | плитки и вложенные: Card M, Stat card, Radio card, Suggest Card, Promo card S, Calendar, Toast Card |
| S | 12 | 8 | `surface/padding/sm` | плашки и поповеры: Card S, Suggest Strip (верх / низ), Date range panel, Dropdown |

Правило выбора: карточка на фоне страницы — L (в том числе карточка с таблицей и карточки сущностей списком); карточка внутри карточки / листа и плитка — M; плашка в строку и всплывающее — S. **Исключение — карточка-список** (внутри только List item / Transaction): Padding S — горизонтальный отступ даёт сама строка, иначе он двойной (23.11). Больше не используются: 28 (Chart card), 32 (Card L, Modal, Promo L по бокам), 20 (Input amount) — сведены к ступеням.

Токены (23.11): `layout/gutter` Compact 12 · Medium 12 · Expanded 16 · Large 16 · XLarge 16 (было 16 / 16 / 24 / 24 / 32); `space/section` 24 · 32 · 40 · 40 · 48 (было 32 / 40 / 40 / 48 / 64); `card/gap` 8 (было 12); новые `surface/padding/lg|md|sm`, `surface/gap`.

Высоты (не отступы, но ритм): строка таблицы — `size/table/row-sm` 48 (одна строка в ячейке; Мониторинг 51–56 → 48) или `size/row/lg` 64 (две строки / медиа); шапка таблицы `size/table/header` 44; строка списка — `list/item-height` (Web 48, App 56).

Радиусы: карточка на фоне — `radius/container` 16; плитка внутри карточки — `radius/inner` 12; лист / модалка / auth — `radius/surface` 24. Радиус 12 у внешних карточек (Мониторинг) и 6 (B2C Payouts) → 16.

Что меняется в продуктах при пересборке: Мониторинг — зазор карточек 16 (как был), радиус 12 → 16, строки 52–56 → 48; B2B — каркас Top bar + серый контейнер (52 до контента) → Sidebar + `layout/margin` 40, зазор 12 → 16; B2C — зазор 10 → 12, поле 10 → 16, шапка → первый блок 10 → 12; App — вложенный экран: между карточками `layout/gutter` 12, в листе — `card/gap` 8. Шаблоны — страница «📐 Лейауты» в Components.

### 2.3 Уровни поверхностей (как в макетах)

- L0 `bg/base` — фон страницы, Sidebar лежит на нём как L1.
- L1 `surface/level-1` — карточки секций, таблица целиком, форма.
- L2 `surface/level-2` / `surface/next` — плашки внутри карточки: строка «Статус пула» в сводке дохода, плитки воркеров, поле поиска внутри карточки таблицы, вложенные блоки «Ключевые метрики».

## 3. Блоки

### 3.1 Виджет баланса

- **Где:** Web App — Sidebar (Header), все экраны; App CH Wallet — верх главной; App pool — карточка «С возвращением» на главной; мобильный веб pool — баланс в Top bar; Продукт Geometria — нет.
- **Состав:** подпись «Баланс» (`type/label`), `Amount` (крупное, копейки мельче), «Скрыть баланс» (`Button` Link S) или глаз (`Icon button`), ряд действий — `Icon button` круглые (Web: 3 — пополнить, обмен, вывести; App: 4 с подписями — Пополнить, Конвертер, Перевести, Вывести).
- **Web:** внутри Sidebar, по центру, ширина сайдбара. **Compact:** App — по центру экрана над рядом действий; мобильный веб — сжат до суммы в Top bar с ▾.
- **Правила:** одно главное число на экран; действия — не больше 4, порядок: пополнить → обменять → перевести → вывести; подписи у кнопок обязательны на Compact, на Web — `Tooltip`.
- **Расхождения:** 3 кнопки на Web vs 4 на App; «скрыть» — ссылка (Web) vs глаз (Профиль-сайдбар); WL Profile — баланс внизу сайдбара.

### 3.2 Ряд показателей (Stat card / группа метрик)

- **Где:** Web App — сводка дохода «Добыто / Прогноз / Сумма к выплате», шапка «Воркеры» (хешрейт, средний, реджекты), Мониторинг — сетка 3×2 (Real hashrate, Power…), Продукт — «Время начислений / Сумма к выплате», прошивка — Autotuner.
- **Состав:** `Stat card` × 2–4 или одна `Card` с ячейками через `Divider` (вертикальный); число — `Amount` с единицей; рядом допустим `Badge` («Повысить», «Target reached»); справа одно действие (`Button` Secondary — «Выгрузить отчёт») или `Select compact` монеты.
- **Web:** в ряд, ячейки равной ширины. **Compact:** столбиком в одной карточке, между ячейками `space/16`–`space/20`; на App вторая строка — 2 колонки.
- **Правила:** 2–4 показателя в ряду; больше — вторая строка или таблица; одно действие на ряд; единица мельче и `text/secondary`.
- **Расхождения:** отдельные `Stat card` с зазором vs одна карточка с разделителями (Мониторинг, Web App) — выбрать одно (см. 5). Под сводкой Web App — вложенная плашка L2 «Статус пула» (курс, дневной доход, сложность, блоки) — на Compact становится списком `Key-value row`.

### 3.3 Карточка графика с периодом (Chart card)

- **Где:** Web App и App — хешрейт / реджекты; Продукт — то же (светлая тема); B2B — Revenue / Users / Hashrates / Coins; прошивка — метрики устройства; Мониторинг — Chain’s hashrate / inlet temperature.
- **Состав:** `Chart card`: сверху 1–3 `Chart metric` (значение + подпись), период — справа; `Chart plot` с двумя осями; легенда — `Legend item`.
- **Web:** период — 3 кнопки справа сверху (Web App, Продукт, прошивка: «1 день / 7 дней / 30 дней»); B2B — `Segmented` в тулбаре страницы; Мониторинг — `Segmented` внутри карточки как переключатель серии. **Compact:** метрики столбиком/2 колонки, период — `Segmented` под графиком (App) или над (мобильный веб).
- **Правила (19.11):** период — ряд `Chip` (Web S справа сверху, Compact M на всю ширину равными долями — как в App); не `Segmented` (см. «Иерархия навигации»); переключение серии — `Tabs` S внутри карточки (как в контракте Chart card), не второй `Segmented`; легенда — над графиком (19.11, как в Web App и App; контракт Chart card приведён).
- **Расхождения:** период кнопками (3 отдельных `Button`) vs `Segmented`; период в карточке vs глобальный в тулбаре (B2B); легенда сверху vs снизу.

### 3.4 Сводка воркеров по статусам

- **Где:** Web App и Продукт — колонка справа от графика (Отключённые / Нестабильные / Активные + «Все воркеры»); App — список с `Counter`; B2B — полоса долей + легенда.
- **Состав:** Web: 3 плитки `surface/next` с тонированным фоном по статусу, число крупно, шеврон; App: `List item` × 3 с `Counter` (тон по статусу) + `Button` «Все воркеры». B2B: `Progress` (сегменты) + `Legend item`.
- **Web и мобильный веб (19.11):** 3 `Stat card` Align=Center, Tone Danger / Warning / Neutral, Link — стрелка; ниже Link «Все воркеры». App — `List item` × 3 с `Counter`.
- **Правила (предложение):** порядок — Отключённые → Нестабильные → Активные (проблемы первыми, как в Web App и App); статус не только цветом — подпись всегда; клик ведёт на «Воркеры» с фильтром.
- **Расхождения:** Продукт ставит Активные первыми; цветные плитки (Web) vs строки с `Counter` (App) vs полоса (B2B) — три способа одной задачи.

### 3.11a Загрузка (19.11)

- **Каркас живой:** Sidebar / Top bar, табы разделов, меню экрана (монета, период, вид) и Action bar рисуются сразу и работают; Skeleton — только данные.
- **Данные — State=Skeleton у компонента, той же высоты:** Amount, Chart metric, Key-value row (подпись остаётся, значение — плашка), Stat card, Chip, Legend item, Chart plot, Table cell / header cell, Coin, Avatar, Badge, Date range field. Высота блока при загрузке не меняется — после ответа ничего не прыгает.
- **Тон неизвестен до данных:** Stat card и статусы в загрузке — Tone=Neutral; Amount — Sign=None.
- **Текст без собственного Skeleton** (строки списков, факты) — `Skeleton` Shape=Text / Title той же ширины, что ожидаемый текст.
- Skeleton показываем, если загрузка дольше 1 с; анимация — по контракту Skeleton: общий блик 1.2 с, при «Уменьшить движение» — пульсация прозрачности.

### 3.15 Вход, регистрация, 2FA (26.11, по флоу регистрации)

- **Ошибки сервера про поле (уточнено 26.11):** почта уже есть, номер занят, почта привязана к Google, неверный код, неверная почта или пароль, пароль совпадает со старым — текст ошибки под полем (`text/danger`), поле красное, CTA неактивна, пока ввод не изменят. Плашку, Toast и Snack для этого не используем; при неверной почте или пароле красные оба поля, текст — под паролем.
- **Toast по платформам (по DS, уточнено 26.11):** Web Desktop — Card справа сверху, 24 от краёв вьюпорта; Web Mobile — Card сверху, на 8 ниже статус-бара, поля 16, перекрывает навбар; App — Informer поверх статус-бара и навбара. Контент не сдвигается. Toast — только события вне поля (провайдер не ответил, письмо отправлено).
- **Suggest** внутри страницы — только объявление или предложение; действие в нём — Tertiary S.
- **Выравнивание и отступы (26.11):** заголовок, описание и подсказки под полями на мобильных — по центру (список требований к паролю — слева); навбар 56 на всех экранах, включая welcome; от вьюпорта: сверху до первого блока 80 (навбар 56 + 24), бока 24, кнопка — 24 от низа вьюпорта; между блоками и полями — 24 (под полем есть место для подсказки), заголовок → подзаголовок 12. Web: контент панели прижат к верху, 112 под шапкой браузера.
- **Web Desktop — split:** слева карусель (монета, заголовок, стрелки и точки), справа блок входа; логотип, «Скачать приложение» и язык — в шапке страницы, не внутри блока. Шаги после входа (телефон, антибот, 2FA, выход) — модалки по центру, шапка остаётся над ними. Поддержка — круглый виджет в правом нижнем углу.
- **Мобильный флоу:** логотип, язык и поддержка — только на welcome. Внутри сценария навбар: стрелка назад, шаги (Step progress) для длинных сценариев (телефон — 4, 2FA — 3), крестик справа.

- **Деструктивное окно** («Прервать регистрацию?»): иллюстрация flow/Exit (треугольник «!» из Product 3D), «Остаться» — Primary, «Прервать» — Tertiary Danger (серая подложка, красный текст). Второстепенные кнопки во флоу — Tertiary (серая подложка); Secondary в DS — акцентная подложка, во флоу не используем.
- **Toast Informer:** только App; накладывается на статус-бар и навбар, контент не сдвигается; высота не меньше статус-бара с навбаром.
- **Антибот:** ползунок — белая ручка на обводке бренда с подписью, не сливается с фоном.

Web Mobile и App — шторка на всю ширину от низа вьюпорта (в мобильном вебе — над панелью Safari), высота по контенту, хэндл сверху, отступы 24, снизу в App 58 (24 над home indicator). Home indicator и панель Safari всегда поверх.

Арт заполняет квадрат. Нет сети — status/Error, форма устарела — status/Pending. Локальные компоненты не заводим.

Web — Modal, Web Mobile — полный экран, App — Sheet.

Крестик всегда справа. Заголовок — ниже шапки, в теле окна.

### 4.1 Дашборд

## 6. Паттерны взаимодействия (22.11, цель 3 · H5; источники — Мониторинг, B2B, B2C, прошивка, инвентарь §5)

Одна задача — один способ. Для каждого: когда, как устроено, компоненты, текст, A11y.

### 6.1 Состояния экрана и блока
| Состояние | Когда | Как | Компоненты |
|---|---|---|---|
| Загрузка | данных ещё нет, форма известна | блоки сохраняют размер, числа и строки — Skeleton (State=Skeleton у Stat card, Chart metric, Table row / cell, Amount…); весь экран не блокируется | Skeleton, State=Skeleton |
| Пусто | данных нет по сути («Воркеров пока нет», «Отчётов за 2025 нет») | Empty state в месте блока: что случилось + одно действие | Empty state |
| Пусто по фильтру | фильтры ничего не нашли | Empty state S «Ничего не найдено» + «Сбросить фильтры» | Empty state, Button Text |
| Ошибка загрузки | запрос упал | Suggest Danger над блоком: «Не удалось загрузить …» + «Повторить»; значения — «—» | Suggest (Strip, Danger) |
| Офлайн / нет связи | устройство / сеть недоступны | Suggest Danger над контентом страницы, данные — последние известные с пометкой времени | Suggest |
| Предупреждение | показатель вне нормы (низкий хешрейт, перегрев) | Suggest Warning над блоком; значение в таблице — `text/danger` (Мониторинг) | Suggest, токен `text/danger` |

### 6.2 Подтверждения
- Только для необратимых и массовых действий: удалить, сбросить, перезагрузить, перевести N устройств.
- Modal Size=SM (`size/modal/sm` 400, заголовок Heading/LG): заголовок-вопрос с объектом («Удалить 4 устройства?»), одна строка последствий, Footer=Horizontal — **[Отмена · Tertiary] [Действие · Primary или Danger]**, как в компоненте Modal; Danger — для удаления. Без иллюстраций, без одиночной кнопки.
- Обратимые действия — без подтверждения, с Toast «Сохранено» / «Скопировано».

### 6.3 Где показывать детали и формы
| Что | Web | Compact |
|---|---|---|
| Детали объекта с разделами | отдельная страница: Page header + Tabs | экран Inner (Top bar с «назад») |
| Быстрый просмотр / короткая форма до 6 полей | Side panel (справа, `size/side-panel`) | Sheet |
| Короткая форма 1–3 поля, подтверждение | Modal sm 400 / md 560 | Sheet |
| Фильтры сверх 4 в строке | Side panel «Фильтры» | Sheet «Фильтры» + Floating button |
Широкий Modal (Мониторинг 1128–1230) и Modal для фильтров не используем.

### 6.4 Таблица: выбор, массовые действия, действия строки, «ещё»
- **Выбор строк:** Checkbox первой ячейкой; в шапке — Table header cell **Select all** (Off · Indeterminate · On). Выбранная строка — Table row Selected=On.
- **Массовые действия:** при первом выборе появляется **Bulk action bar** (Web — плавающая по центру над низом окна, `space/24`; Compact — над Tab bar): «Выбрано N из M», до двух действий, «⋯» — остальные (удаление — там, с подтверждением 6.2), «Снять выбор» (и Esc). Пока полоса видна, контенту страницы добавляется нижний отступ: высота полосы + `space/24` — она не закрывает «Load more» и последние строки.
- **Действия строки:** одно — Icon button Tertiary S в последней ячейке; два и больше — «⋯» → Menu; удаление — только в Menu.
- **Итог:** счётчики по статусам и «Всего N» — в шапке карточки таблицы (Status · число), а не отдельной карточкой снизу.
- **Много строк:** «Load more» — Button Secondary M по центру под таблицей; Pagination — только в отчётах.
- **Колонки:** ширина — под содержимое (Table row · слот Cells); колонка без данных (у всех «none» / «—») не показывается; числа — у конца, текст — у начала.

### 6.5 Поиск и фильтры
- Поиск по списку — Search M в начале тулбара карточки, фильтрует таблицу по мере ввода (дебаунс в коде), пусто → 6.1 «Пусто по фильтру».
- Поиск с подсказками (B2B: ID / имя / почта) — Search + Dropdown panel со строками Menu item в две строки, совпадение — Medium; Enter / клик — открыть объект. (Вариант набора — кандидат, раздел 5.)
- Фильтры: до 4 в строке над таблицей (Select на рамке, Date range field, Chip-период); больше — 6.3. «Сбросить фильтры» — Button Text, когда хоть один фильтр не по умолчанию.
- Период: Chip; один период на страницу — в Page header, свой у блока — в шапке Chart card / карточки.

### 6.6 Формы: валидация и несохранённые изменения
- Ошибка поля — после ухода с поля или отправки: рамка Danger + текст под полем; кнопка отправки не прячется.
- Главная кнопка формы — disabled, пока нет изменений (настройки) или форма невалидна (вход, регистрация).
- Несохранённые изменения: в шапке формы — «Есть несохранённые изменения» + активная «Сохранить»; при закрытии Side panel / Sheet / уходе со страницы — подтверждение 6.2 «Выйти без сохранения?» [Остаться · Secondary] [Выйти · Danger].

### 6.7 Обратная связь
- Toast — результат обратимого действия (сохранено, скопировано, пул добавлен): справа сверху (Web), над Tab bar (Compact), 4–6 с, с «✕».
- Копирование (ID, адрес, хеш, IP) — Icon button Ghost XS «copy» рядом с текстом → Toast «Скопировано».
- Status screen — результат операции, после которого нужно следующее действие (вывод создан, Watcher link создан — «Скопировать ссылку»).
- Tooltip графика — Chart tooltip (дата + серии) по наведению / стрелками.

## 5. Вопросы и кандидаты в парковку

### Одна задача — разные способы (решено 16.11 — см. раздел 0)

1. **Навигация на мобильном вебе pool:** бургер + `Tabs`, без `Tab bar`; App и WL — `Tab bar`. Контракт `Tab bar`: «одна схема для App и мобильного веба».
2. **Sidebar на Web:** плавающий (Web App, Мониторинг) / во всю высоту (Продукт Geometria) / меню внутри контейнера + Top bar (B2B admin).
3. **Детали объекта:** страница (Web App) / широкий `Modal` (Мониторинг, ≈1156) / `Side panel` (прошивка) / `Sheet` (Compact). Предложение: Web — `Side panel` для быстрого просмотра, страница — когда у объекта есть `Tabs`; `Modal` не использовать.
4. **Период графика:** 3 отдельные `Button` / `Segmented` / глобальный тулбар страницы.
5. **Статус-фильтр списка:** `Tabs` с `Counter` (Web App, WL) против правила Tabs «не фильтр». Либо `Chip`-ряд, либо явное исключение в контракте Tabs.
6. **Ряд метрик:** отдельные `Stat card` vs одна карточка с вертикальными разделителями.
7. **Сводка воркеров:** цветные плитки / строки с `Counter` / полоса долей.
8. **Детали строки истории:** раскрытие на месте (WL) vs `Sheet` (контракт Transaction).
9. **Подтверждение успеха:** зелёный экран / Status screen / `Toast`.
10. **«Сохранить» в формах настроек:** вверху справа (прошивка) / внизу (WL) / без кнопки (Toggle).
11. **Реферальное предложение:** `Suggest` Strip сверху vs `Promo card` снизу; ряд из 3 промо против правила «одна промо-карточка на экран».
12. **Подпись поля:** над полем (Web App) / на рамке (WL, Продукт, прошивка) — в формах вне калькулятора контракт Input требует Above.
13. **Строки таблицы:** с `Divider` внутри L1 (Web App, B2B) vs строки-карточки (Мониторинг).

### Кандидаты в парковку (нет в Base)

- **Top bar** (мобильная шапка: «назад», заголовок, аккаунт / баланс / действия) — упоминается в контрактах `Page header`, `Tab bar`, `Sheet`, набора нет.
- **Stepper** — набор-обёртка над `Step` + `Step trail` (KYB); сейчас только части.
- **Table** — контейнер таблицы (шапка, строки, итоговая строка, липкая шапка, горизонтальная прокрутка); сейчас только `Table row` / `Table cell` / `Table header cell`.
- **Тулбар фильтров** (Search + Select + Date range field + «Очистить», перенос в Sheet на Compact).
- **Search** как отдельный вариант (глобальный поиск с выпадающими результатами — B2B).
- **Карусель** (карточки банковских карт, монеты Coinhold, шаги «Как начать» на App) — горизонтальная прокрутка с `Page indicator`.
- **Group header / Section header** — заголовок секции с подзаголовком и одним действием справа (повторяется в Настройках, B2B analytics, дашборде).
- **Setting row** — строка «иконка + название + описание + контрол справа» с перестройкой на Compact (сейчас собирается из `List item` с Trailing, проверить, хватает ли).
- **Key-value row с точечной линией-лидером** (прошивка) — вариант или не делаем.
- **Медиум / Expanded раскладки** — ни одного макета: нужны эталоны дашборда и таблицы на 768 и 1024.
