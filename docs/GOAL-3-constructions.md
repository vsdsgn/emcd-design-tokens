# Цель 3: система конструкций, лейаутов и паттернов на Мониторинге и WL (поставлена 2026-11-21)

**Цель.** На экранах Мониторинга (Web + мобильный веб), WL B2B admin (Web) и WL B2C (клиент, App / мобильный веб) выстроить одну систему: отступы (шкала + правила «что каким интервалом»), лейауты экранов по платформам и продуктам, конструкции (организмы / виджеты) с правилами применения, паттерны взаимодействия (состояния, подтверждения, панели, фильтры, массовые действия). Атомы и молекулы — довести полировку (все варианты, состояния, отступы — на токенах, без расхождений Figma ↔ код). Собрать организмы → виджеты → страницы → разделы; экраны пересобраны из DS и сверены с production глазами; код повторяет экраны.

Почему эти продукты: у них похожие конструкции (сводка, график с периодом, таблица с фильтрами, детали объекта, настройки), но много отличий — на них система проверяется, а не подгоняется под один продукт.

Работаю автономно. Publish, `stable`, изменение существующих токенов Foundations — только Стефан (копится в «Очереди»). Экраны — только в файлах Migration test.

## Источники (production)
- **Мониторинг** — Главная, Площадки, Устройства, Детали устройства, Отчёты, Сотрудники, Уведомления, Сканер (Web 1440 + мобильный 375).
- **WL B2B admin** — Analytics, Users (список + профиль), Reports, Settings, Fee, Watcher-link (Web 1440).
- **WL B2C** (клиент) — Statistics, Workers, Payouts, Watcherlink, Profile, Auth (375; бренд WL Default).
- **Веб-интерфейс прошивки** (reviewed dashboard) — справочник состояний: загрузка, офлайн, предупреждения, подтверждения, панели, несохранённые изменения, ошибки полей. Экраны не пересобираем, берём паттерны.
