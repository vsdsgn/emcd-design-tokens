## Дефекты (править в Figma)
- [листы 01–02 и все ячейки · все пары On / Off, например экземпляры 1 и 2, 3 и 4, 19 и 20] Border = On меняет геометрию: высота растёт на 2 px (S 58 vs 56, M 66 vs 64, L 82 vs 80), слот `content` сдвигается внутрь на 1 px с каждой стороны (замер: слот x = 30…324 при On против 29…325 при Off). Обводка учитывается в раскладке (или паддинг On на 1 px больше). → Переключение Border не должно двигать содержимое и менять высоту: обводка внутрь без учёта в auto layout (`Strokes: exclude`), высота при On = Off (S 56 · M 64 · L 80).

## Заметки (не дефект / на решение)
- Уровни (Level N — карточка на L(N−1)), Light, замер цвета:
  - Level 1 (`surface/level-1` #f5f5f5) на L0 (#fff) — видна, но контраст подложки ~1.09:1; с Border = Off на белом почти пропадает (листы 01–09, экземпляры 2, 4, 6…). Совпадает с правилом описания «Border = On на L0 в светлой теме» — правило нужно оставить жёстким.
  - Level 2 (#ececec) на L1 (#f5f5f5) — читается и без обводки (лист 11).
  - Неверные пары ведут себя ожидаемо: Level 1 на L1 и Level 2 на L2 сливаются с фоном при Off (листы 10, 14 — видна только обводка); на L2 / L3 карточка младшего уровня светлее фона, «утоплена» (листы 13, 16–17). На L3 обводка `border/subtle` (чёрный 8 %) поверх светлой карточки по цвету ≈ фону L3 — обводка исчезает (лист 16–17). Это не дефект набора: Level задаётся вручную по вложенности, карточка не адаптируется к подложке (`surface/current` не используется).
- Уровни, Dark:
  - Level 1 (#1a1a1a) на L0 (#0a0a0a) — хорошо отделяется (листы 37–45).
  - Level 2 (#202020) на L1 (#1a1a1a) — шаг очень мал (~1.07:1), при Border = Off карточка почти сливается (лист 47, экземпляры 20, 22, 24…). Правило «Border = On — соседние уровни» здесь фактически обязательно; на решение: в Dark для Level 2+ рекомендовать Border = On явно.
  - На L2 / L3 карточки Level 1–2 темнее фона («яма»), листы 49–54 — неверное применение, ожидаемо.
  - `surface/raised` набор не использует (заливки только `surface/level-0…3`), так что неопубликованный подъём `surface/raised` → neutral/700 на Card не влияет.
- Бренды: Geometria радиусы меньше (замер ≈ Container 8, Surface 12, Inner 4 против EMCD / WL 16 / 24 / 8) — от токенов `radius/*` бренда, корректно. В Geometria Container и Surface визуально различимы слабо (8 vs 12). WL Default совпадает с EMCD пиксель в пиксель.
- Платформы: iOS / Android не отличаются от Web — ожидаемо, размеры от платформы не зависят.
- Описание: пишет «Level 1–3» и числа радиусов «Surface 24 · Container 16 · Inner 8», а ось Level содержит и 0 (Level 0 — вариантов 37–72, во второй половине), и радиусы зависят от бренда. На решение: дописать правило Level 0 (из CHANGELOG: «на ревью») и оговорку «числа — для EMCD». Порядок значений оси `1, 2, 3, 0` — 0 в конце, нелогично (на решение — переставить 0 первым).
- Слот `content`: плейсхолдер — пунктир `border/default`, радиус `radius/xs`; виден во всех экземплярах. Это заглушка шаблона, при подстановке содержимого заменяется — не дефект; проверить, что плейсхолдер не уходит в код / на экраны.
- Ширина корня — число 320 без токена (`raw: (root):w=320`); для шаблона-контейнера ширина задаётся раскладкой (Fill) — не дефект, отметить в контракте.
- Текст и языки (лист 73): у набора нет текстовых свойств — ячейки long / de / ar / hi / th / ja / kk показывают пустой вариант по умолчанию без изменений; проверять нечего, раскладка цела.
- 200 % (лист 73): все варианты без изменений (текста нет), обрезок нет.
- Свойства: булевых свойств нет (`props: []`), ячеек «Свойство · …» нет; служебных слоёв (Focus ring, hit area, Safe margin) нет — для неинтерактивного контейнера ожидаемо.
- Борда: нет разделов 04, 05, 07, 08, 12 (по манифесту).
