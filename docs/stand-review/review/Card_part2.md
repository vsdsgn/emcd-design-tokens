## Дефекты (править в Figma)
- [листы 01–72 · все ячейки · пары экземпляров 1/2, 3/4 … 35/36] Border = On меняет геометрию, как и в части 1: высота +2 px (S 58 против 56, M 66 против 64, L 82 против 80), слот `content` сужается на 1 px с каждой стороны (замер: x 30…324 при On против 29…325 при Off; сдвиг сверху 17 против 16). → Переключение Border не двигает содержимое: обводка внутрь без учёта в auto layout, высота On = Off (S 56 · M 64 · L 80).
- [описание набора · ось Level] Level 0 (экз. 19–36, половина этой части) в описании не упомянут: «Level 1–3 = surface/level-*», правило «страница L1, внутри карточки L2, …» про 0 молчит; значения оси идут `1, 2, 3, 0` — 0 в конце. → Дописать правило Level 0 в описание (на борде уже есть предложение: «белая карточка на подложке L1 с обводкой On, на странице L0 без обводки не ставим»); 0 поставить первым или оставить с пометкой в описании.

## Заметки (не дефект / на решение)
- Соответствие Level ↔ поверхность (замер заливки против подложки ячейки): Light — Level 3 = #e0e0e0 = подложка L3 (лист 16), Level 0 = #fff = подложка L0 (лист 02); Dark — Level 3 = #262626 = подложка L3 (лист 52), Level 0 = #0a0a0a = подложка L0 (лист 38). Токены `surface/level-3` и `surface/level-0` совпадают с уровнями стенда в обеих темах — верно.
- Level 3 на своей подложке (L2), Light: #e0e0e0 на #ececec — читается и без обводки (лист 13). Dark: #262626 на #202020 — шаг ~1.07:1, при Border = Off карточка почти сливается (лист 49, экз. 2, 4, 6 … 18). Как и Level 2 в части 1: в Dark для Level 2–3 Border = On фактически обязателен — на решение, записать в правило явно.
- Level 3 на L3 и Level 0 на L0 при Border = Off сливаются с фоном полностью (листы 16, 52 — экз. 2, 4 …; листы 02, 38 — экз. 20, 22 …): видна только заглушка `content`. Это неверное применение (на L0 без обводки Level 0 не ставим — по правилу с борды), не дефект отрисовки.
- Level 0 на L1–L3: в Light — белая карточка, светлее фона («поднята», листы 11, 14, 17); в Dark — #0a0a0a, темнее фона («яма», листы 47, 50, 53). Формулировка с борды «белая карточка» верна только для Light — на решение: в Dark Level 0 читается как утопленная плашка, проверить, нужен ли он там.
- Обводка `border/subtle` у Level 0 на L0: Light #ebebeb на #fff (~1.2:1), Dark #1d1d1d на #0a0a0a — видна еле-еле (листы 02, 38, экз. 19, 21 …). Ожидаемо для «subtle»; правило «на L0 без обводки не ставим» держится на очень слабой линии — на решение.
- `surface/raised` набор не использует (заливки только `surface/level-0…3`), поэтому неопубликованный подъём `surface/raised` (Dark → neutral/700) Card не затрагивает; скриншоты для Card актуальны.
- Бренды: Geometria — радиусы меньше (замер ≈ Container 8 · Surface 12 · Inner 2–4 против EMCD / WL 16 · 24 · 8), от токенов `radius/*` бренда — корректно. В Geometria Inner почти прямой угол.
- Описание даёт числа радиусов «Surface 24 · Container 16 · Inner 8» — это EMCD; на решение: оговорка «числа — для EMCD, у брендов свои».
- Порядок значений Radius `Container, Surface, Inner` (16 · 24 · 8) не монотонный — не дефект (Container по умолчанию первым), отметить.
- Текст и языки (лист 73): текстовых свойств нет, ячейки long / de / ar / hi / th / ja / kk показывают пустой вариант (здесь — Level 3 · Container · S · On) без изменений; раскладка цела.
- 200 % (лист 73): все 36 вариантов без изменений (текста нет), обрезок нет.
- Свойств (`props: []`) и служебных слоёв нет — ячеек «Свойство · …» нет; для неинтерактивного контейнера ожидаемо.
- Слот `content` — пунктир-заглушка (`border/default`, `radius/xs`), виден во всех экземплярах; заменяется содержимым.
