## 1. Неизменяемые решения (не пересматривать)

- Оси: Brand (EMCD · Geometria · WL Default) × Theme (Light · Dark) × Platform (Web · Mobile web · iOS · Android) × Viewport × Style (Base по умолчанию · Expressive только pool и Monitoring). Компоненты используют только семантические токены.
- Шкала: 2 4 6 8 10 12 16 20 24 28 32 40 48 56 64; без нечётных и дробных. Исключения — только из `docs/exceptions.md`.
- Состояния: Hover / Pressed — один слой `state/layer` (6 % / 10 %), цвета не подменяются. Disabled — подложка 8 %, контент 40 %, вложенные контролы тоже Disabled. Selected — `accent/subtle` + `text/accent`; сплошной только у выбранной даты и отмеченных контролов.
- Кольцо фокуса: нейтральное, рамка на 2 px больше родителя, обводка OUTSIDE, `border/width/focus-ring`, радиус `radius/focus-ring*` по родителю.
- Размеры контролов: S32 таблицы/тулбары · M40 Web · L48 App · XL56 главный CTA. Hit area — два слоя web/app, в коде `max(размер, touch/min)`. Safe margin — `control/safe-margin`; OS safe area — `os/safe-area/*`.
- Текст: кнопки и подобные не обрезаются и не переносятся (растут до max-width, Button 280); многоточие — только поля, селекты, списки. 19 языков, RTL, 200 % текста.
- Статус никогда не только цветом. Контраст: WCAG 2.2 блокирует, APCA — отчёт.
- Input: лейбл виден всегда, плейсхолдер — подсказка, без плавающих лейблов.
- Card — гибкий атом-шаблон без жёстких слотов. Badge и Counter — разные компоненты. Toast = Card | Informer; Snack — отдельный; Suggest — бывшие Alert + Banner.
- Имена: Start / End вместо Left / Right (кроме Tooltip); в коде без префикса `E`.
- Всё финансовое / Coinhold — не развивать. Performa — только донор.

## 3. План работ

### Фаза A. Инвентаризация (только чтение, ~первые часы)
1. Снять из Figma Components манифест: на каждый набор — уровень (atom/molecule/organism), страница и статус, оси и значения, свойства (тип, дефолт, привязаны ли во всех вариантах), вложенные экземпляры (какой компонент внутри), токены по слоям, непривязанные числа, размеры max/min, наличие слоёв focus / hit area / safe margin, наличие и полнота борды v3 (разделы 00–12).
2. Сохранить как `docs/ds-manifest.json` (+ генератор в `scripts/figma/manifest.plugin.js`). Это будущий единый источник для parity, Claude DS, доки и бордов.
3. Снять тот же манифест со стороны кода, что доступно: `build/**` (токены), `claude-ds/components`, Storybook shared-web (адрес в LINKS.md) и DSP, если доступен без VPN. Что недоступно — записать, а ожидаемое API из Figma положить в `docs/dsp-check-*.md`.
4. Отчёт расхождений `docs/audit-<дата>.md`: Figma ↔ правила (п. 1), Figma ↔ код, компонент ↔ компонент той же семьи.

### Фаза B. Системные основы атомов (то, чего сейчас нет)
Сейчас похожие компоненты собраны каждый по-своему. Вынеси общее в базовые служебные компоненты (префикс `_`, не публикуются отдельно, либо публикуются как base — решение запиши с обоснованием):
- `_Focus ring` — одна рамка по правилу кольца.
- `_State layer` — один слой Hover / Pressed.
- `_Hit area` и `_Safe margin` — зоны.
- `_Field base` — общая база Input, Textarea, Select, Multiselect, Password field, Date range field, Input amount, Code input (рамка, подпись, notch, helper, counter, отступы, кольцо, Disabled / Read-only / Error / Loading / Skeleton).
- `_Selection control` — общая коробка Checkbox / Radio / Toggle + подпись + helper.
- `_List row` — Menu item, Multiselect option, List item, Dropdown panel row.
- `_Overlay surface` — Tooltip, Dropdown panel, Sheet, Modal, Toast (уровень, тень, радиус, отступы).
Сначала сделай `_Field base` и перестрой на нём Input + Textarea (пилот). Прогони все проверки, запиши результат в HANDOFF и **оставь Стефану одну доску «⚑ Пилот базы полей»**; пока он не ответил — продолжай фазу A/C по атомам, которые от пилота не зависят.

### Фаза C. Атомы, затем молекулы — по одному рецепту
Порядок: атомы по алфавиту страниц → молекулы. На каждый компонент:
1. Legacy-основа и продуктовые примеры (Web App, App, Monitoring, Firmware, WL B2B, Geometria) — найти, записать в контракт, откуда взято.
2. Собрать на базовых служебных компонентах, все размеры/отступы/радиусы/цвета на переменных.
3. Оси и состояния по модели п. 1; убрать неполные комбинации вариантов или задокументировать, почему их нет.
4. Контракт в `docs/components/<name>.md` (и строкой в манифест): назначение, когда / когда нет, жёсткое правило выбора каждого варианта, свойства и дефолты, токены, состояния, motion, хаптики, a11y (роль, ARIA, клавиатура, фокус, читалка), длинный текст и локали, RTL, min/max размеры по платформам, Base / Expressive, API для Vue и Flutter, миграция с legacy.
5. Тот же текст — в описании компонента в Figma (первая строка `Status:`), борда по шаблону v3 с Default в каждом превью.
6. Проверки (п. 4). Красное → исправить → снова прогнать.
7. Commit + push с понятным сообщением; строка в HANDOFF.

### Фаза D. Код и паритет
